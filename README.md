# linqwq

> 为 Android 打造的 Linux 沙盒

## 这是什么

在 Android 设备上运行完整的 Linux 用户空间，并把体验做到"能当桌面用"——不是套一层 VNC 看个界面就完事。

## 现状与差距

Termux、proot-distro 这类方案证明了这条路能走，但用起来都不舒服。卡在三件事：

1. **没有硬件加速** —— 容器里的 X/Wayland 全靠 CPU 软件渲染，滚动和动画都是幻灯片
2. **图形是转发出来的** —— 走 VNC 或 X11 socket，多一层搬运就多一层延迟，触摸尤其钝
3. **与 Android 割裂** —— 输入法、剪贴板、文件、通知，全是两个世界

linqwq 的目标就是把这三件事逐个解决。

## 核心设计

### 1. 容器层

在 Android 上提供 Linux 用户空间。可选路径：

- **root + chroot + mount namespace** —— 性能最好，接近裸机；要求设备可 root
- **proot** —— 无需 root，靠 ptrace 拦截系统调用；通用但有 2–5 倍开销
- **user namespace** —— 最优雅，但绝大多数 Android 内核关闭了 `CONFIG_USER_NS`

### 2. 图形加速

让容器内的图形程序真正用上 GPU，而不是软渲染。候选路径：

- **VirGL** —— 把容器里的 GL 调用转发到宿主 GPU，已有 Android 移植，目前最成熟
- **Zink** —— OpenGL over Vulkan，Mesa 生态内可复用
- **直接暴露 DRM** —— 需要内核与 root 支持，Android 的 KGSL 并非标准 DRM，风险高

### 3. 系统集成

这一层决定"能不能当日常用"：

- **输入法** —— 容器内的 text-input 协议桥接到 Android IME
- **剪贴板** —— Android ClipboardManager 双向同步
- **文件** —— Android 存储与容器目录的双向映射
- **通知** —— 容器内事件投递到 Android 通知栏

### 4. 显示层

自建合成器，取代 VNC / X11 转发：

- 直接跑在 Android GPU 上
- 圆角、阴影、模糊、动画自己实现
- 触摸手势与窗口管理重新设计，不移植键盘快捷键

## 技术栈

| 层 | 选型 | 状态 |
| --- | --- | --- |
| 语言 | C++20 | 已定 |
| 图形（桌面开发） | OpenGL 3.3 Core · GLFW · libepoxy | 已定 |
| 图形（Android） | OpenGL ES 3.x | 已定 |
| 容器 | chroot / proot | **待验证** |
| 图形加速 | VirGL | **待验证** |
| 构建 | CMake + NDK | 已定 |
| 目标平台 | Android 12+ | 已定 |

渲染与交互逻辑先在桌面环境开发调试，再移植到 Android。shader 主体共用，仅版本行与 precision 不同。
